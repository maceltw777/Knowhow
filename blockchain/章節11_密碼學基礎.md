## 11.1 密碼雜湊函數

密碼雜湊函數把任意長度輸入映射為固定長度輸出（digest），是區塊鏈中最基礎的原語——區塊鏈的「鏈」、地址、Merkle 樹、PoW 全都靠它。

### 三大安全性質

| 性質 | 定義 | 若被破解 |
|------|------|---------|
| 抗原像性（Preimage） | 給定 `h`，難以找出 `m` 使 `hash(m)=h` | 可從地址反推私鑰相關資訊 |
| 抗第二原像（2nd Preimage） | 給定 `m1`，難以找出 `m2≠m1` 使雜湊相同 | 可偽造特定交易 |
| 抗碰撞（Collision） | 難以找出任意一對 `m1≠m2` 雜湊相同 | 可偽造 Merkle 證明、雙花 |

另加**雪崩效應**（輸入改 1 bit，輸出約半數 bit 翻轉），使雜湊「不可預測」，這正是 PoW 需要暴力嘗試的原因。

### 區塊鏈常用雜湊

```python
import hashlib

def sha256(data: bytes) -> bytes:
    return hashlib.sha256(data).digest()

def double_sha256(data: bytes) -> bytes:
    """Bitcoin 的 HASH256：兩次 SHA-256（防長度擴展攻擊）"""
    return hashlib.sha256(hashlib.sha256(data).digest()).digest()

def keccak256(data: bytes) -> bytes:
    """Ethereum 使用；注意 ≠ NIST 標準化的 SHA3-256（padding 不同）"""
    from Crypto.Hash import keccak          # pycryptodome
    k = keccak.new(digest_bits=256)
    k.update(data)
    return k.digest()

def hash160(data: bytes) -> bytes:
    """Bitcoin 地址：RIPEMD160(SHA256(x))，縮短輸出至 160 bit"""
    return hashlib.new("ripemd160", hashlib.sha256(data).digest()).digest()
```

| 演算法 | 輸出 | 用途 | 備註 |
|--------|------|------|------|
| SHA-256 | 256 bit | Bitcoin PoW、Merkle 樹 | Merkle–Damgård 結構 |
| Keccak-256 | 256 bit | Ethereum 地址/儲存槽/事件 | 與 SHA3-256 padding 不同 |
| RIPEMD-160 | 160 bit | Bitcoin 地址（配 SHA256） | 縮短地址長度 |
| SHA-3 (Keccak) | 可變 | 新標準 | Sponge 結構 |

> **常見誤區**：Ethereum 的 `keccak256` 是 SHA-3 競賽提交的原始 Keccak，**不等於**最終 NIST 標準化的 SHA3-256（兩者 domain padding 不同，輸出不同）。撰寫跨語言程式時務必用對。

### Merkle–Damgård vs Sponge

```
Merkle–Damgård（SHA-256）        Sponge（Keccak / SHA-3）
                                  吸收(absorb)      擠出(squeeze)
m1   m2   m3                       m1  m2            │
 │    │    │                        │   │            │
 ▼    ▼    ▼                       ┌┴┐ ┌┴┐         ┌─▼─┐
IV─▶[f]─▶[f]─▶[f]─▶ digest        │f│▶│f│▶ … ▶│f│─▶ digest
     壓縮函數鏈式迭代               固定容量狀態，可變長輸出
     ⚠ 有長度擴展攻擊              ✓ 天生免疫長度擴展攻擊
```

Merkle–Damgård 的長度擴展弱點，正是 Bitcoin 用 **double SHA-256** 的原因。Keccak 的 Sponge 結構天生免疫，且能輸出可變長度（可當 XOF 使用）。

## 11.2 橢圓曲線密碼學

橢圓曲線密碼學（ECC）是區塊鏈簽章的核心。相較 RSA，ECC 用小得多的金鑰達到同等安全（256-bit ECC ≈ 3072-bit RSA），非常適合鏈上空間受限的場景。

### 有限體與曲線

區塊鏈用的橢圓曲線定義在**有限體 `F_p`**（模某大質數 p 的整數）上，方程式為：

```
y² = x³ + ax + b  (mod p)
```

secp256k1（Bitcoin/Ethereum 使用）取 `a=0, b=7`，即 `y² = x³ + 7`。曲線上的點加上一個「無窮遠點」`O` 構成一個**循環群**，其上定義了「點加法」。安全性來自**橢圓曲線離散對數難題（ECDLP）**：已知基點 `G` 與 `P = k·G`，求 `k` 在計算上不可行——`k` 就是私鑰，`P` 就是公鑰。

### 點運算實作

```python
# secp256k1 參數
P  = 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEFFFFFC2F
A, B = 0, 7
Gx = 0x79BE667EF9DCBBAC55A06295CE870B07029BFCDB2DCE28D959F2815B16F81798
Gy = 0x483ADA7726A3C4655DA4FBFC0E1108A8FD17B448A68554199C47D08FFB10D4B8
N  = 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFEBAAEDCE6AF48A03BBFD25E8CD0364141  # 群的階

def inv(x, m=P):
    return pow(x, m - 2, m)                    # 費馬小定理求模反元素

def point_add(p1, p2):
    if p1 is None: return p2
    if p2 is None: return p1
    (x1, y1), (x2, y2) = p1, p2
    if x1 == x2 and (y1 + y2) % P == 0:
        return None                             # 互為反元素 → 無窮遠點
    if p1 == p2:                                # 倍點：切線斜率
        m = (3 * x1 * x1 + A) * inv(2 * y1) % P
    else:                                       # 相異點：割線斜率
        m = (y2 - y1) * inv(x2 - x1) % P
    x3 = (m * m - x1 - x2) % P
    y3 = (m * (x1 - x3) - y1) % P
    return (x3, y3)

def scalar_mult(k, point):
    """k·G，用 double-and-add，O(log k)"""
    result, addend = None, point
    while k:
        if k & 1:
            result = point_add(result, addend)
        addend = point_add(addend, addend)
        k >>= 1
    return result

G = (Gx, Gy)
private_key = 0xC0FFEE...                       # 32 bytes 隨機數（0 < k < N）
public_key = scalar_mult(private_key, G)         # 公鑰 = 私鑰 × G
```

「公鑰 = 私鑰 × G」正向極快、逆向（ECDLP）不可行，這條單行道就是整個非對稱密碼學的心臟。

### 曲線比較

| 曲線 | 體大小 | 主要用途 | 特點 |
|------|--------|---------|------|
| secp256k1 | 256-bit | Bitcoin、Ethereum 簽章 | Koblitz 曲線，運算可優化 |
| Curve25519 (Ed25519) | 255-bit | Solana、Near、多數新鏈 | 更快、抗側信道、無需選 k |
| BN254 / alt_bn128 | 254-bit | ZK-SNARK、Ethereum 預編譯 | 支援配對（pairing） |
| BLS12-381 | 381-bit | Ethereum 信標鏈 BLS 簽章 | 配對友善、安全裕度更高 |

## 11.3 ECDSA 簽章

ECDSA（橢圓曲線數位簽章演算法）是 Bitcoin 與 Ethereum 的簽章標準。

### 簽章與驗證

```python
import hashlib, os

def sign_ecdsa(msg_hash: int, priv: int) -> tuple:
    while True:
        k = int.from_bytes(os.urandom(32), "big") % N   # ⚠ 每次簽名須用全新隨機 k
        if k == 0:
            continue
        x, _ = scalar_mult(k, G)
        r = x % N
        if r == 0:
            continue
        s = (inv(k, N) * (msg_hash + r * priv)) % N
        if s == 0:
            continue
        return (r, s)

def verify_ecdsa(msg_hash: int, sig: tuple, pub: tuple) -> bool:
    r, s = sig
    if not (0 < r < N and 0 < s < N):
        return False
    w  = inv(s, N)
    u1 = (msg_hash * w) % N
    u2 = (r * w) % N
    x, _ = point_add(scalar_mult(u1, G), scalar_mult(u2, pub))
    return (x % N) == r
```

簽章是一對 `(r, s)`。驗證者用公鑰重算，確認結果與 `r` 一致——只有握有私鑰者能產出合法 `s`，但任何人都能驗證。

### 可恢復簽章與 ecrecover

Ethereum 為了省空間，交易**不附帶公鑰**，而是從簽章反推出簽署者地址。這需要簽章多帶一個 1-bit 的 **recovery id `v`**（標示 `R` 點的 y 座標奇偶與象限），使 `(v, r, s)` 能唯一還原公鑰：

```
簽章 (v, r, s) + 訊息雜湊
        │  ecrecover
        ▼
   還原公鑰 → keccak256(pubkey)[-20:] → 簽署者地址
```

Solidity 的 `ecrecover(hash, v, r, s)` 預編譯正是做這件事。**安全陷阱**：`ecrecover` 對無效輸入回傳 `address(0)` 而非報錯，合約若不檢查 `!= address(0)` 就可能被繞過（見 [章節12 智能合約安全](章節12_智能合約安全.md)）。此外 ECDSA 有「簽章可鍛性」（`s` 與 `N-s` 都合法），EIP-2 要求 `s` 取低半區間以防交易雜湊被竄改。

### k 值重用災難

ECDSA 最致命的實作錯誤：**兩筆不同訊息用了同一個 `k`**。此時攻擊者可直接解出私鑰：

```python
def recover_private_key(msg1, r, s1, msg2, s2):
    """若兩簽章共用 k（故 r 相同），任何人可還原私鑰"""
    k    = ((msg1 - msg2) * inv((s1 - s2) % N, N)) % N   # 先反解 k
    priv = ((s1 * k - msg1) * inv(r, N)) % N             # 再解私鑰
    return priv
```

歷史慘案：**2010 PlayStation 3**（Sony 固定 k，私鑰全洩）、**2013 Android SecureRandom 漏洞**（弱隨機導致 k 碰撞，多個 Bitcoin 錢包被盜）。

**防禦：RFC 6979 確定性 k**——用 `k = HMAC(priv, msg_hash)` 由私鑰與訊息確定性地推導 `k`，既不依賴隨機源、又保證不同訊息得到不同 `k`。現代錢包一律採用。

## 11.4 Schnorr 簽章與 Taproot

Schnorr 簽章比 ECDSA 更簡潔、且具備 ECDSA 缺乏的**線性性（linearity）**，這帶來強大的聚合能力。Bitcoin 於 2021 Taproot 升級（BIP-340）採用 Schnorr。

**線性性**：多個簽章可相加成單一簽章，多個公鑰可相加成單一公鑰。這使「多方共同簽署」在鏈上看起來與「單人簽署」完全相同：

```
一般多簽              Schnorr 聚合 (MuSig2)
sig_A, sig_B, sig_C   sig_agg = sig_A + sig_B + sig_C
pub_A, pub_B, pub_C   pub_agg = pub_A + pub_B + pub_C
鏈上：3 把簽章+3 把公鑰   鏈上：1 把簽章 + 1 把公鑰
（大、貴、隱私差）        （小、便宜、外界看不出是多簽）
```

```python
def schnorr_sign(msg_hash: int, priv: int, nonce: int) -> tuple:
    R = scalar_mult(nonce, G)                    # 承諾點
    e = int.from_bytes(sha256(str((R[0], msg_hash)).encode()), "big") % N
    s = (nonce + e * priv) % N
    return (R[0], s)                             # (R_x, s)

def schnorr_verify(msg_hash, sig, pub) -> bool:
    Rx, s = sig
    e = int.from_bytes(sha256(str((Rx, msg_hash)).encode()), "big") % N
    # 檢查 s·G == R + e·P
    left  = scalar_mult(s, G)
    right = point_add((Rx, _recover_y(Rx)), scalar_mult(e, pub))
    return left[0] == right[0]
```

**MuSig2** 是安全的多方 Schnorr 聚合協議（解決了 nonce 交互與惡意公鑰攻擊）。**Taproot** 結合 Schnorr 聚合與 MAST，讓複雜的多簽/腳本花費在鏈上與普通轉帳無異，兼顧隱私、成本與彈性。

## 11.5 BLS 簽章與配對

BLS（Boneh–Lynn–Shacham）簽章的殺手級特性是**非交互式聚合**：把來自不同人、對不同訊息的成千上萬個簽章，聚合成**單一**簽章，一次驗證。這正是 Ethereum 信標鏈的需求——每個 slot 有數萬驗證者投票。

**配對（Pairing）**：BLS 依賴雙線性映射 `e(aP, bQ) = e(P, Q)^(ab)`。這個「把指數搬出來」的性質讓驗證方程得以成立，但需要「配對友善曲線」（如 BLS12-381）。

```python
# 概念示意（真實需配對曲線 e: G1 × G2 → GT）
def bls_sign(msg, priv):
    H = hash_to_curve(msg)          # 訊息映射到曲線上一點
    return scalar_mult(priv, H)     # σ = priv · H(m)

def bls_verify(msg, sig, pub):
    # e(σ, G) == e(H(m), pub)  ⟺  e(priv·H, G) == e(H, priv·G)
    return pairing(sig, G) == pairing(hash_to_curve(msg), pub)

def bls_aggregate(sigs):
    """N 個簽章 → 1 個，驗證成本幾乎不變"""
    agg = None
    for s in sigs:
        agg = point_add(agg, s)
    return agg
```

| 特性 | ECDSA | Schnorr | BLS |
|------|-------|---------|-----|
| 簽章大小 | 64–65 B | 64 B | 48 B（更小） |
| 需隨機 nonce | 是（k 風險） | 是 | **否**（確定性） |
| 聚合 | 不支援 | 需交互（MuSig2） | **非交互，任意聚合** |
| 驗證成本 | 低 | 低 | 較高（配對運算） |
| 主要使用者 | Bitcoin、以太坊 EOA | Bitcoin Taproot | 以太坊信標鏈 |

Ethereum 信標鏈選 BLS，正是看中「數萬驗證者的投票可聚合成單一簽章驗證」（回鏈 [章節03 PoS](章節03_共識機制與安全性.md)）；代價是驗證含配對運算、成本較高。

## 11.6 承諾方案

承諾方案（Commitment Scheme）讓你先「封存」一個值（**hiding**，別人看不出內容），事後再「揭示」且無法反悔（**binding**，不能改成別的值）。[章節03](章節03_共識機制與安全性.md) 的 RANDAO 提交-揭示、ZKP、Rollup 資料承諾都用到它。

**Pedersen 承諾**：`C = v·G + r·H`（`v` 是要承諾的值，`r` 是隨機致盲因子，`H` 是另一個無人知道對 `G` 之離散對數的生成點）。具備**加法同態**：`C(v1) + C(v2) = C(v1+v2)`，讓機密交易能在不揭露金額下驗證「輸入總和 = 輸出總和」（Monero、機密交易用之）。

```python
def pedersen_commit(v, r, H):
    return point_add(scalar_mult(v, G), scalar_mult(r, H))   # C = vG + rH
```

**KZG 多項式承諾**：用單一橢圓曲線點承諾一整個多項式 `f(x)`，並能為「`f(z)=y`」提供**常數大小**的證明——無論多項式多大，證明都只有一個群元素。這是現代 ZK 系統與 Ethereum 擴展的關鍵：

- **PLONK 等 zk-SNARK**（[章節05](章節05_隱私保護技術.md)）用 KZG 承諾電路多項式。
- **EIP-4844 Proto-Danksharding**（[章節14](章節14_現代以太坊技術.md)）用 KZG 承諾 blob 資料，讓 Rollup 能廉價地把資料掛上以太坊並證明可用性。

```
KZG 承諾直覺
多項式 f(x)  ──承諾──▶  單一點 C = f(τ)·G   （τ 為可信設定的秘密）
想證明 f(z)=y ──▶ 附一個證明點 π
驗證者用配對檢查：e(C - y·G, G) == e(π, (τ-z)·G)   常數大小、常數時間
```

> **🔄 技術更新（2025+）**：**後量子密碼學**正在標準化。量子電腦的 Shor 演算法能破解 ECDLP（威脅 ECDSA/Schnorr/BLS），NIST 已於 2024 標準化 ML-DSA（Dilithium）、SLH-DSA（SPHINCS+）等後量子簽章。區塊鏈界正研究遷移路徑——難點在於後量子簽章體積大得多（數 KB），對鏈上空間與聚合是新挑戰；雜湊函數（SHA-256）則相對抗量子（Grover 僅將安全性減半），影響較小。
