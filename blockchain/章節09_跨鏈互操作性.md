## 9.1 跨鏈橋接技術

### 跨鏈橋接協議實現

跨鏈橋允許資產和信息在不同區塊鏈之間傳遞，是 DeFi 多鏈生態的基礎設施。

#### 橋接類型

```python
from enum import Enum
from dataclasses import dataclass, field
from typing import Dict, List, Optional
import hashlib
import time

class BridgeType(Enum):
    LOCK_MINT = "lock_mint"       # 鎖定-鑄造（最常見）
    BURN_MINT = "burn_mint"       # 銷毀-鑄造（原生資產）
    LIQUIDITY_POOL = "liq_pool"   # 流動性池（無需發行包裝代幣）

class TransactionStatus(Enum):
    PENDING = "pending"
    LOCKED = "locked"             # 源鏈已鎖定
    RELAYED = "relayed"           # 中繼節點已確認
    MINTED = "minted"             # 目標鏈已鑄造
    COMPLETED = "completed"
    FAILED = "failed"
```

#### CrossChainBridge 主類

```python
class CrossChainBridge:
    def __init__(self, bridge_type: BridgeType):
        self.bridge_type = bridge_type
        self.supported_chains: Dict[str, dict] = {}   # chain_id → config
        self.validators: List[str] = []               # 驗證者地址列表
        self.threshold: int = 0                       # 最少需要的驗證者簽名數
        self.pending_txs: Dict[str, CrossChainTransaction] = {}
        self.nonce_tracker: Dict[str, int] = {}       # 防止重放攻擊
    
    def register_chain(self, chain_id: str, config: dict):
        """注冊支持的區塊鏈"""
        required_fields = ['rpc_endpoint', 'bridge_contract', 'native_token']
        for field in required_fields:
            if field not in config:
                raise ValueError(f"缺少必要配置：{field}")
        
        self.supported_chains[chain_id] = {
            **config,
            'registered_at': int(time.time()),
            'is_active': True
        }
    
    def add_validator(self, validator_address: str):
        """添加橋接驗證者"""
        if validator_address not in self.validators:
            self.validators.append(validator_address)
            self.threshold = len(self.validators) * 2 // 3 + 1  # 2/3 多數決
    
    def initiate_cross_chain_transfer(self,
                                       source_chain: str,
                                       target_chain: str,
                                       sender: str,
                                       recipient: str,
                                       token: str,
                                       amount: int) -> str:
        """發起跨鏈轉帳"""
        if source_chain not in self.supported_chains:
            raise ValueError(f"不支持源鏈：{source_chain}")
        if target_chain not in self.supported_chains:
            raise ValueError(f"不支持目標鏈：{target_chain}")
        
        tx_id = self._generate_tx_id(source_chain, target_chain, sender, amount)
        
        # 根據橋接類型確定目標代幣
        target_token = self._get_target_token(token, source_chain, target_chain)
        
        tx = CrossChainTransaction(
            tx_id=tx_id,
            bridge_type=self.bridge_type,
            source_chain=source_chain,
            target_chain=target_chain,
            source_token=token,
            target_token=target_token,
            sender=sender,
            recipient=recipient,
            amount=amount
        )
        
        self.pending_txs[tx_id] = tx
        
        # 在源鏈執行鎖定/銷毀操作
        source_tx_hash = self._execute_source_chain_action(tx)
        tx.source_tx_hash = source_tx_hash
        tx.status = TransactionStatus.LOCKED
        
        return tx_id
```

#### 驗證流程

```python
class CrossChainBridgeValidator:
    """驗證者：監聽源鏈事件，驗證並中繼到目標鏈"""
    
    def __init__(self, bridge: CrossChainBridge, private_key: bytes):
        self.bridge = bridge
        self.private_key = private_key
        self.address = self._derive_address(private_key)
    
    def monitor_and_relay(self, source_chain: str):
        """持續監聽源鏈的橋接事件"""
        chain_config = self.bridge.supported_chains[source_chain]
        
        while True:
            events = self._fetch_bridge_events(chain_config['rpc_endpoint'])
            
            for event in events:
                tx_id = event['tx_id']
                if tx_id in self.bridge.pending_txs:
                    self._process_event(event)
    
    def _process_event(self, event: dict):
        """處理橋接事件"""
        tx_id = event['tx_id']
        tx = self.bridge.pending_txs[tx_id]
        
        # 1. 驗證源鏈交易（等待足夠確認數）
        if not self._verify_source_tx(tx, event):
            return
        
        # 2. 生成簽名
        message = self._create_relay_message(tx)
        signature = self._sign_message(message)
        
        # 3. 廣播簽名（通過 P2P 網絡或鏈上）
        self.bridge.submit_validator_signature(tx_id, self.address, signature)
    
    def _verify_source_tx(self, tx: CrossChainTransaction, event: dict) -> bool:
        """驗證源鏈交易的真實性"""
        required_confirmations = {
            'ethereum': 12,
            'bitcoin': 6,
            'polygon': 64,
            'bsc': 15
        }
        
        chain_confirmations = required_confirmations.get(tx.source_chain, 12)
        return event.get('confirmations', 0) >= chain_confirmations
    
    def _create_relay_message(self, tx: CrossChainTransaction) -> bytes:
        """創建中繼消息（由所有驗證者簽名）"""
        data = (
            tx.tx_id.encode() +
            tx.target_chain.encode() +
            tx.recipient.encode() +
            tx.target_token.encode() +
            tx.amount.to_bytes(32, 'big')
        )
        return hashlib.sha256(data).digest()
```

#### 跨鏈驗證（Merkle 證明）

```python
class CrossChainProofVerifier:
    """驗證跨鏈 Merkle 證明"""
    
    def verify_cross_chain_proof(self, tx: CrossChainTransaction) -> bool:
        """
        完整的跨鏈驗證流程：
        1. 驗證 Merkle 包含性證明（交易存在於源鏈區塊中）
        2. 驗證區塊頭（工作量或權益證明）
        3. 驗證交易收據（交易確實被執行）
        """
        if tx.merkle_proof is None:
            return False
        
        proof = tx.merkle_proof
        
        # 步驟 1：驗證 Merkle 路徑（交易哈希 → Merkle Root）
        if not self._verify_merkle_path(
            proof['tx_hash'],
            proof['merkle_path'],
            proof['block_header']['merkle_root']
        ):
            return False
        
        # 步驟 2：驗證區塊頭有效性（PoW/PoS）
        if not self._verify_block_header(proof['block_header'], tx.source_chain):
            return False
        
        # 步驟 3：驗證該區塊是源鏈的一部分（防止孤塊欺騙）
        if not self._verify_chain_ancestry(proof['block_header']['hash'], tx.source_chain):
            return False
        
        # 步驟 4：驗證收據中的事件（確認橋接事件已發出）
        if not self._verify_receipt_logs(proof['receipt'], tx):
            return False
        
        return True
    
    def _verify_merkle_path(self, leaf_hash: str, path: List[dict], expected_root: str) -> bool:
        """驗證 Merkle 路徑"""
        current = leaf_hash
        
        for node in path:
            sibling = node['hash']
            is_left = node['is_left']
            
            if is_left:
                combined = sibling + current
            else:
                combined = current + sibling
            
            current = hashlib.sha256(bytes.fromhex(combined)).hexdigest()
        
        return current == expected_root
    
    def _verify_block_header(self, header: dict, chain: str) -> bool:
        """驗證區塊頭（針對不同共識機制）"""
        if chain == 'bitcoin':
            return self._verify_pow_header(header)
        elif chain in ['ethereum', 'polygon']:
            return self._verify_pos_header(header)
        return False
    
    def _verify_pow_header(self, header: dict) -> bool:
        """驗證 PoW 區塊頭"""
        block_hash = hashlib.sha256(
            hashlib.sha256(self._serialize_header(header)).digest()
        ).hexdigest()
        
        # 區塊哈希必須小於目標難度
        target = int(header['bits'], 16)
        return int(block_hash, 16) < target
    
    def _verify_receipt_logs(self, receipt: dict, tx: CrossChainTransaction) -> bool:
        """驗證收據中包含橋接事件"""
        bridge_event_signature = hashlib.sha256(
            b'BridgeTransfer(address,address,uint256,bytes32)'
        ).hexdigest()
        
        for log in receipt.get('logs', []):
            if (log.get('address') == self.bridge_contract_address and
                log.get('topics', [None])[0] == bridge_event_signature):
                
                # 驗證事件中的金額和地址
                decoded = self._decode_bridge_event(log)
                if (decoded['recipient'] == tx.recipient and
                    decoded['amount'] == tx.amount):
                    return True
        
        return False
```

#### 目標鏈動作執行

```python
class CrossChainExecutor:
    """在目標鏈執行橋接動作"""
    
    def execute_on_target(self, tx: CrossChainTransaction, 
                           validator_signatures: List[dict]) -> str:
        """
        驗證簽名並在目標鏈鑄造/解鎖代幣
        """
        # 1. 驗證簽名數量達到閾值
        if len(validator_signatures) < self.bridge.threshold:
            raise ValueError(f"簽名不足：{len(validator_signatures)}/{self.bridge.threshold}")
        
        # 2. 驗證每個簽名
        relay_message = CrossChainBridgeValidator(None, None)._create_relay_message(tx)
        valid_sigs = 0
        
        for sig_data in validator_signatures:
            if (sig_data['signer'] in self.bridge.validators and
                self._verify_sig(relay_message, sig_data['signature'], sig_data['signer'])):
                valid_sigs += 1
        
        if valid_sigs < self.bridge.threshold:
            raise ValueError("有效簽名不足")
        
        # 3. 防重放檢查（nonce 追蹤）
        nonce_key = f"{tx.source_chain}:{tx.tx_id}"
        if nonce_key in self.bridge.nonce_tracker:
            raise ValueError("交易已處理（重放攻擊防護）")
        self.bridge.nonce_tracker[nonce_key] = int(time.time())
        
        # 4. 在目標鏈執行操作
        if tx.bridge_type == BridgeType.LOCK_MINT:
            target_tx = self._mint_wrapped_token(
                tx.target_chain, tx.target_token, tx.recipient, tx.amount
            )
        elif tx.bridge_type == BridgeType.BURN_MINT:
            target_tx = self._mint_native_token(
                tx.target_chain, tx.target_token, tx.recipient, tx.amount
            )
        else:
            target_tx = self._release_from_pool(
                tx.target_chain, tx.target_token, tx.recipient, tx.amount
            )
        
        tx.target_tx_hash = target_tx
        tx.status = TransactionStatus.COMPLETED
        
        return target_tx
```

## 9.2 原子交換與 HTLC

9.1 的橋大多依賴外部驗證者（有信任假設）。**原子交換（Atomic Swap）** 走另一條路：兩人直接在兩條鏈上互換資產，靠密碼學保證「要嘛兩邊都成功，要嘛兩邊都退款」，全程無需第三方託管。其核心工具是 **HTLC（Hash Time-Locked Contract，雜湊時間鎖合約）**。

### HTLC 原理

HTLC 在資產上加兩道鎖：

- **雜湊鎖（Hash Lock）**：資金只有出示某個秘密 `s`（其雜湊 `H = hash(s)` 事先公開）才能領取。
- **時間鎖（Time Lock）**：若在期限前無人出示秘密，發起方可退款。

```python
import hashlib, time

class HTLC:
    def __init__(self, sender, receiver, amount, hashlock, timelock):
        self.sender = sender
        self.receiver = receiver
        self.amount = amount
        self.hashlock = hashlock       # H = sha256(secret)
        self.timelock = timelock       # 絕對到期時間（unix 秒）
        self.claimed = False
        self.refunded = False

    def claim(self, preimage: bytes, now: int):
        """接收方出示秘密領款（在到期前）。"""
        if self.claimed or self.refunded:
            raise ValueError("已結算")
        if now >= self.timelock:
            raise ValueError("已過期，只能退款")
        if hashlib.sha256(preimage).hexdigest() != self.hashlock:
            raise ValueError("秘密不符（雜湊鎖未開）")
        self.claimed = True
        return preimage                # 秘密被公開，供對鏈使用

    def refund(self, now: int):
        """逾期後，發起方取回資金。"""
        if self.claimed or self.refunded:
            raise ValueError("已結算")
        if now < self.timelock:
            raise ValueError("尚未到期，不能退款")
        self.refunded = True
```

### 跨鏈原子交換流程

假設 Alice 想用鏈 A 的資產換 Bob 在鏈 B 的資產。關鍵在於**兩邊用同一個 `hashlock`，但 Alice 的時間鎖較長**，確保 Bob 一旦領款、Alice 必能在自己的期限內跟著領。

```
1. Alice 生成秘密 s，計算 H = hash(s)
2. Alice 在鏈 A 部署 HTLC(收款人=Bob, hashlock=H, timelock=T2)   ← 較長
3. Bob 看到後，在鏈 B 部署 HTLC(收款人=Alice, hashlock=H, timelock=T1)  ← 較短 (T1 < T2)
4. Alice 用 s 領取鏈 B 的資金 → 秘密 s 在鏈 B 上被公開
5. Bob 讀到公開的 s，用它領取鏈 A 的資金
   ✅ 交換完成，全程無第三方

失敗情境：任一方中途退出 → 雙方都在各自 timelock 後 refund，無人損失
```

**為何 Alice 的鎖要更長**：若兩邊等長，Bob 可能拖到 Alice 快到期才領款，讓 Alice 來不及在鏈 A 領款。`T1 < T2` 保證 Alice 領款後，Bob 仍有時間反應。閃電網路的多跳付款正是把多個 HTLC 串成一條路徑（見 [章節06 → 狀態通道](章節06_網路擴展性與Layer2.md)）。原子交換的無信任度最高，代價是慢、需雙方在線、且只能換資產不能傳遞任意訊息。

## 9.3 輕客戶端與信任最小化驗證

要「無需信任外部驗證者」地確認另一條鏈的狀態，理想做法是讓目標鏈自己**驗證源鏈的共識**——這就是輕客戶端（Light Client）的角色。

### 輕客戶端證明

全節點驗證整條鏈；輕客戶端只驗證區塊頭鏈與少量 Merkle 證明，即可確認「某交易確實被源鏈最終化」。跨鏈時，可在鏈 B 上以合約形式部署鏈 A 的輕客戶端：

```python
class OnChainLightClient:
    """部署在鏈 B 上的合約，追蹤鏈 A 的區塊頭並驗證其共識。"""

    def __init__(self, trusted_header, validator_set):
        self.head = trusted_header              # 起始可信檢查點
        self.validators = validator_set         # 源鏈當前驗證者集

    def update_head(self, new_header, signatures):
        """僅在新頭被源鏈 >2/3 權益簽署時才接受。"""
        signed = self._sum_stake(signatures)
        if signed <= (2 / 3) * self._total_stake():
            raise ValueError("簽名權益不足，拒絕更新")
        if new_header.parent_hash != self.head.hash:
            raise ValueError("非連續區塊頭")
        self.head = new_header

    def verify_tx(self, tx_hash, merkle_path):
        """在已確認的頭上驗證交易包含性。"""
        return self._merkle_verify(tx_hash, merkle_path, self.head.tx_root)
```

信任被縮到最小：只信「源鏈的驗證者集不會 >1/3 作惡」——這與源鏈自身的安全假設相同，故稱「信任最小化」。

### Cosmos IBC

**IBC（Inter-Blockchain Communication）** 是 Cosmos 生態的原生跨鏈標準，正是輕客戶端方案的成熟實作。每條鏈為對方維護一個輕客戶端，訊息以「封包（packet）」傳遞：

```
鏈 A                          中繼者 (Relayer)                    鏈 B
 │ 1. send_packet             (無需信任，只搬運)                    │
 │───────────────────────────────────────────────────────────────▶│
 │                                        2. 鏈 B 上的 A-輕客戶端    │
 │                                           驗證封包 + Merkle 證明  │
 │                                        3. recv_packet 執行        │
 │◀───────────────────────────────────────────────────────────────│
 │ 4. acknowledge （附帶逾時退款 timeout 保護）                     │
```

Relayer 只負責搬運訊息，**無法偽造**（鏈 B 的輕客戶端會驗證），因此 IBC 屬於「原生驗證」信任等級。IBC 已透過 IBC Everywhere 等計劃擴展到 Cosmos 生態之外（含 Ethereum）。

### ZK 輕客戶端

輕客戶端的痛點是：在 EVM 上重跑另一條鏈的共識驗證（尤其 BLS 簽章聚合）**gas 昂貴**。**ZK 輕客戶端**用零知識證明把「我驗證過源鏈共識」壓成一個小證明，鏈上只需驗證該證明：

- **Succinct SP1 Helios**：用 ZK 證明驗證 Ethereum 信標鏈的同步委員會簽章，讓任何鏈都能廉價、無需信任地追蹤 Ethereum 狀態。
- 這被視為跨鏈安全的「終局解」：信任假設等同源鏈共識，且驗證成本被 ZK 攤薄（ZK 原理見 [章節05 隱私保護技術](章節05_隱私保護技術.md)）。

## 9.4 跨鏈訊息傳遞協議

橋（9.1）主要搬**資產**；而現代跨鏈需求是搬**任意訊息**（呼叫遠端合約、跨鏈治理、全鏈 NFT）。這催生了通用訊息傳遞（Generic Message Passing）協議。

### LayerZero V2

LayerZero V2（2024）的核心是把「驗證」與「執行」解耦，讓應用自選安全等級：

```
來源鏈 dApp ──emit──▶  [DVN 們]  ──驗證訊息──▶  目標鏈 Endpoint ──▶ 目標 dApp
                        ↑ 去中心化驗證網路              ▲
                   應用可自選 1~N 個 DVN 組合            │
                                              [Executor] 負責在目標鏈
                                                        觸發執行（付 gas）
```

- **DVN（Decentralized Verifier Network，去中心化驗證網路）**：負責背書「這則訊息真的來自來源鏈」。應用可要求多個獨立 DVN 同時確認（X-of-Y），安全性由應用自訂。
- **Executor**：與驗證分離，只在訊息通過驗證後於目標鏈代付 gas 執行。
- 已整合 70+ 條鏈，是跨鏈訊息傳遞的市場領導者。

### Chainlink CCIP

**CCIP（Cross-Chain Interoperability Protocol）** 走企業級路線，被 SWIFT 等傳統金融機構用於跨鏈測試：

- 建立在 Chainlink 既有的去中心化預言機網路之上。
- 獨立的 **Risk Management Network（RMN）** 作為第二道防線，獨立監控並可在偵測到異常時暫停跨鏈通道（雙網路防護）。

### 通用訊息 vs 資產橋

| 維度 | 資產橋（9.1） | 通用訊息協議（LayerZero/CCIP/IBC） |
|------|--------------|-----------------------------------|
| 傳遞內容 | 主要是代幣 | 任意 payload（含合約呼叫） |
| 典型用途 | 跨鏈轉帳、包裝資產 | 全鏈應用、跨鏈治理、跨鏈借貸 |
| 信任模型 | 多依賴外部驗證者 | 可配置（DVN 組合 / RMN / 輕客戶端） |
| 代表 | Arbitrum Bridge、Hop | LayerZero、CCIP、IBC |

## 9.5 跨鏈安全模型與信任光譜

跨鏈是區塊鏈損失最慘重的領域——理解各方案的**信任假設**比追逐功能更重要。所有跨鏈設計可放在一條「信任光譜」上：越往右信任假設越小、安全性越高，但通常越慢或越貴。

### 信任光譜

```
信任更多 ◀─────────────────────────────────────────────▶ 信任最小
外部驗證                    最佳化/樂觀                    原生驗證
(External)                  (Optimistic)                  (Native)
   │                            │                            │
單一/多簽託管            欺詐證明 + 挑戰期           輕客戶端 / ZK 證明
Multichain              Nomad、Across              IBC、ZK Light Client
Ronin                                              原子交換 HTLC
   │                                                        │
安全性 = 驗證者誠實          安全性 = 至少一個              安全性 = 源鏈共識本身
(可被私鑰洩露攻破)          誠實挑戰者 + 資料可用           (信任假設最小)
```

- **外部驗證**：最快、最泛用，但安全性取決於一組外部驗證者，私鑰洩露即失守（Ronin 之鑑）。
- **最佳化驗證**：靠欺詐證明，只需一個誠實挑戰者，但有挑戰期延遲。
- **原生驗證**：直接驗源鏈共識（輕客戶端/ZK/HTLC），信任假設最小，是行業公認的方向。
