## 14.1 MEV

MEV（Maximal Extractable Value，最大可提取價值）指出塊者藉由**任意排序、插入、審查區塊內交易**所能額外攫取的價值。因為出塊者決定交易順序，而順序在 DeFi 中直接等於利潤。

### 主要類型

- **套利（Arbitrage）**：跨 DEX 價差套利，通常良性、有助價格收斂。
- **清算（Liquidation）**：搶先執行可清算倉位賺取清算獎勵。
- **三明治攻擊（Sandwich）**：夾擊受害者的大額 swap——前面搶跑推高價、受害者以更差價成交、後面賣出獲利。

```python
def sandwich_attack(pool, victim_amount):
    """在受害者買單前後夾擊套利。"""
    # 1. front-run：搶在受害者前面買入，推高價格
    bought = pool.swap(attacker_in=victim_amount)      # 攻擊者先買
    price_before = pool.price()
    # 2. 受害者的交易在被推高的價格上成交（滑價更大）
    pool.swap(victim_in=victim_amount)
    # 3. back-run：攻擊者賣出，賺取價差
    profit = pool.swap(attacker_out=bought) - victim_amount
    return profit                                       # 受害者的滑價 = 攻擊者利潤
```

### Flashbots 與 PBS

早期 MEV 競逐造成公開記憶池的「搶跑 gas 戰爭」，堵塞網路。**Flashbots** 引入私有交易通道與 MEV 拍賣，把混亂搬到鏈下有序競價。這演化為**提議者-建設者分離（PBS, Proposer-Builder Separation）**：

```
搜尋者(Searcher)  建構者(Builder)        提議者(Proposer=驗證者)
發現 MEV 機會 ─▶ 把交易打包成完整區塊 ─▶ 出價競標 ─▶ 驗證者只挑「出價最高」的區塊頭簽名
                  （競爭誰的區塊最有價值）           （看不到內容，防止自己竊取 MEV）
```

PBS（目前以 **MEV-Boost** 中介軟體實現）讓驗證者無須自建複雜 MEV 系統即可分享收益，也降低了因 MEV 導致的中心化壓力（承接 [章節03 PoS 的 PBS callout](章節03_共識機制與安全性.md)）。未來目標是 **ePBS**——把 PBS 直接寫進協議層，去除對 MEV-Boost 中繼的信任。

## 14.2 帳戶抽象與 ERC-4337

以太坊有兩種帳戶：**EOA（外部帳戶，私鑰控制）** 與**合約帳戶**。傳統上只有 EOA 能發起交易，這帶來諸多限制：只能用 ECDSA 簽章、gas 必須用 ETH 付、私鑰遺失即永久失去資產。**帳戶抽象（Account Abstraction）** 讓錢包本身成為可程式化的智能合約。

**ERC-4337** 在不改動以太坊協議的前提下實現帳戶抽象，引入一套獨立於原交易的流程：

```
使用者 ──簽 UserOperation──▶ 專用 mempool
                                  │
                            Bundler 打包多個 UserOp
                                  │
                                  ▼
                          EntryPoint 合約（唯一入口）
                          ├─ 呼叫各 Smart Account 驗證簽章
                          ├─ 執行帳戶邏輯
                          └─ 向 Paymaster 結算 gas
```

- **UserOperation**：使用者意圖的「偽交易」物件，進專用 mempool。
- **Bundler**：把多個 UserOp 打包成一筆真實交易送上鏈（賺取手續費）。
- **EntryPoint**：受信任的單一入口合約，統一驗證與執行。
- **Paymaster**：可代付 gas——讓 dApp 補貼手續費，或讓使用者**用 USDC 等代幣付 gas**，無需持有 ETH。

帳戶抽象解鎖的能力：**社交恢復**（用親友/裝置多方恢復錢包，取代助記詞）、批次交易（approve + swap 一次完成）、自訂簽章方案（passkey、多簽）、支出限額等可程式化安全策略。

> **🔄 EIP-7702（Pectra，2025）**：讓現有 EOA 能在單筆交易期間「暫時」擁有合約程式碼，即刻享有帳戶抽象能力（批次、代付、自訂驗證），無需遷移到新合約錢包地址。這是帳戶抽象普及的關鍵一步（回鏈 [章節03 Pectra 升級](章節03_共識機制與安全性.md)）。

## 14.3 EIP-4844 Proto-Danksharding

Rollup（[章節06](章節06_網路擴展性與Layer2.md)）必須把資料發布到 L1 以繼承其安全性。EIP-4844 之前，資料存在昂貴的 `calldata`，成為 Rollup 成本的大頭。**EIP-4844（2024 Dencun 升級）** 引入 **blob（大型二進位物件）** ——一種便宜、且會**自動過期**的資料空間，專為 Rollup 設計。

```
傳統 calldata：永久存於以太坊歷史，與 EVM 執行共用 gas → 貴
blob：
  ┌─ 每個 blob ≈ 128 KB，掛在區塊「旁邊」，EVM 不可讀取其內容
  ├─ 只保留約 18 天（DA 窗口）後可裁剪 → 節點不需永久儲存
  ├─ 用「blob gas」獨立市場計價（EIP-1559 式），與一般 gas 分離
  └─ 以 KZG 承諾（見章節11.6）證明資料完整、可供驗證
```

**為何用 KZG 承諾**：blob 內容 EVM 看不到，但合約需要一個小小的「指紋」來指涉並驗證它。KZG 多項式承諾（[章節11.6](章節11_密碼學基礎.md)）正好提供常數大小的承諾與開啟證明，讓 Rollup 能在鏈上證明「我用的資料就是這個 blob」。

**效果**：blob 有獨立的供需市場，需求低時 blob gas 極便宜，使 Rollup 的資料成本下降約一個數量級，L2 手續費隨之大幅降低。這是「Rollup-centric roadmap」落地的關鍵一步——它把擴展的瓶頸從「執行」轉向「資料可用性」。

## 14.4 資料可用性

**資料可用性（Data Availability, DA）問題**：出塊者是否真的公布了「重建狀態/驗證所需的全部資料」？若出塊者發布區塊頭卻扣住部分資料，別人就無法驗證或（對 Rollup 而言）無法退出。這正是 [章節06](章節06_網路擴展性與Layer2.md) 中 Plasma 的致命傷，也是 Rollup 必須把資料上鏈的原因。

**資料可用性抽樣（DAS, Data Availability Sampling）**：與其要求每個節點下載全部資料，不如讓每個輕節點**隨機抽樣**其中幾小片。搭配**糾刪碼（erasure coding）**——把資料擴展成有冗餘的編碼，使「只要有一半碎片就能還原全部」——則只要少量誠實抽樣者的樣本都拿得到，就能以極高機率確信「全部資料都可用」。

```
原始資料 ─糾刪碼擴展→ [ d1 d2 d3 d4 | p1 p2 p3 p4 ]  （加入冗餘碎片）
                        任意 4/8 碎片即可還原全部
輕節點各隨機抽 k 片檢查是否可取得：
  若出塊者藏起 >50% 資料 → 幾乎必被某個抽樣者發現 → 判定不可用
  抽樣越多、被藏資料越難蒙混，安全性指數上升
```

**專用 DA 層**：把 DA 從執行鏈分離出來，形成獨立、便宜的資料層供 Rollup 使用：

| DA 方案 | 特點 |
|---------|------|
| Ethereum blob (4844) | 安全性最高，直接繼承以太坊共識；成本較外部 DA 高 |
| Celestia | 模組化區塊鏈的專用 DA 層，DAS 原生設計 |
| EigenDA | 建於 EigenLayer 再質押之上，高吞吐 |
| Avail | Polygon 系的獨立 DA 層 |

選用外部 DA（而非以太坊 blob）的 Rollup 常被稱為 **Validium / Optimium**，成本更低但安全性取決於該 DA 層而非以太坊——又一個回到信任取捨的選擇。

## 14.5 Danksharding 路線圖

EIP-4844 是「Proto」-Danksharding——它先鋪好 blob 的交易格式與市場，但每個區塊僅少量 blob（目標約 3、上限約 6）。**完整 Danksharding** 的願景是把 blob 容量擴大到每區塊數十甚至上百個（目標吞吐達每秒數 MB 的 DA），使以太坊成為所有 Rollup 的巨型資料可用性層。

其路線圖上的關鍵技術：

- **2D KZG 承諾**：把 blob 資料排成二維並在行列上都做 KZG 承諾與糾刪碼，讓 DAS 更高效、抽樣保證更強。
- **PeerDAS**：邁向完整 Danksharding 的過渡步驟，讓節點在 P2P 網路中只保管與交換部分 blob 資料並互相抽樣，逐步實現分散式 DA，而非要求人人存全部。
- **與 SSF 的關係**：完整 Danksharding 的高吞吐 DA 需搭配更快的最終性；**單槽最終性（SSF）**（見 [章節03](章節03_共識機制與安全性.md)）讓每個 slot 即最終化，兩者共同支撐「大規模 Rollup + 快速確定性」的終局架構。

```
EIP-4844 (2024)          PeerDAS               完整 Danksharding
少量 blob/區塊     ─▶  節點分散抽樣交換 blob  ─▶  數十~上百 blob/區塊
先驗證市場與格式        逐步分散 DA 負擔          以太坊 = 統一 DA 層
```

> **🔄 技術更新（2025+）**：以太坊路線圖的其他前沿——**Verkle Trees / 無狀態性（Statelessness）**：用 Verkle 樹取代 Merkle Patricia 樹，大幅縮小狀態證明，讓「無狀態客戶端」（不需存全狀態即可驗證區塊）成為可能，降低節點門檻。**Rollup 去中心化**：目前多數 L2 的排序者（Sequencer）仍中心化，正朝去中心化排序、強制包含（force inclusion）與無需信任的提款推進。整體方向是把「執行外包給 L2、以太坊專注共識與資料可用性」的模組化架構做到極致。
